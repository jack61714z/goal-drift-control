# Goal drift control

Perform the alignment review and apply its disposition within the authority you actually hold. A review that identifies drift but leaves the affected action unchanged is incomplete. This skill does not grant permissions, add an approval stage, require a second person, or replace the host's existing investigation and review contracts.

## Recover the real task

Read the original intended outcome, current slice, effective scope decisions, actual cumulative artifacts and proposed next action. Recover exclusions, freezes, deferrals, exact authorized exceptions and unfinished parent obligations. A link or summary is insufficient when its unread contents could change the decision.

Identify the actual decision owner and allowed effects. Do not infer authority from tools, filenames or another model's verdict. Reuse valid evidence and existing task identities. A clarification is not automatically new work.

If a material source is unavailable, retain UNKNOWN for the affected claim and name the smallest observation that would resolve it. Continue unrelated authorized work. A real defect does not reopen deferred work, and broader understanding does not authorize broader implementation.

## Inspect both directions

Compare original requirements to actual implementation and observations, then compare each material change to the requirement that justifies it. Review the entire cumulative direction, not only the latest patch or test summary.

Assess these dimensions proportionately in existing review prose:

- Goal: whether the action and outcome serve the original result.
- Scope: boundaries, freezes, deferrals and exact exceptions.
- Interfaces: actual producers, consumers and interactions affected.
- Architecture: whether added structure is necessary for the goal.
- Ownership: responsibility, authority and actual execution.
- Runtime/data/security: relevant behavior, persistence, privacy and security effects.
- Dependencies: real prerequisites, affected neighbors and remaining parent work.

These are dimensions, not seven stages. Explain material UNKNOWN or not-applicable conclusions and what decisions they constrain. A supported material drift finding remains DRIFT_FOUND even if other dimensions are unknown. Use UNKNOWN overall when necessary evidence is missing and no material drift is established. NO_DRIFT_SUPPORTED applies only to the inspected range with sufficient relevant evidence.

## Decide and act

For each material finding distinguish observed fact, original-candidate truth, current acceptance applicability and disposition. Preserve contrary evidence. A resolved, rejected or deferred label does not prove the underlying fact disappeared.

Choose the smallest justified action: proceed, accept a bounded slice, narrow or stop an affected dispatch, request a specific repair or observation, or defer with the proper authority. Apply that decision to the actual next operation. Withhold effects that depend on unresolved drift, while allowing independent authorized work. Do not block every legitimate case merely to avoid false acceptance.

For a behavioral claim, inspect observations that reach its real effect boundary. Use a discriminating counterexample and legitimate success case when needed. Reject tests whose expected result contradicts the requirement; never weaken an oracle merely to make it pass. Reading a skill, counting files, echoing a marker or matching words cannot establish unrelated behavior.

Keep source delivery, installation/loading, actual use, accepted result and parent completion distinct. If the requested result includes working functionality, do not replace that requirement with documentation availability. Conversely, do not invent infrastructure when the authorized outcome is genuinely only a document.

## Return evidence of the decision

Use the caller's existing record and authorized destination. State the original goal, cumulative range, evidence actually inspected versus reported, per-dimension reasoning, findings, disposition, operation actually allowed/changed/held and remaining owner/action. Save and read back the record if authorized and required; otherwise disclose the delivery gap.

Attribute user-supplied corrections as such, not autonomous discovery. A successful bounded use does not prove sustained drift prevention. Do not close an unfinished parent because this review or one slice is complete. Return to the original deliverable's next incomplete transition.

This package operates independently. It does not own tracker mechanics, closure learning, transport or record schemas. Removing it does not remove already-authorized scope decisions or review duties.
